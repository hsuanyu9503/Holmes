# 606 情報局｜連線模式 v2.5.0 測試版（2026-10-24）

> 以 v2.4.39 單機正式版為基礎，新增 `online.html`、`assets/online.js`、`assets/online.css`、`online-config.js`、`supabase/606-online-v2.5.0.sql`；不更動既有單機遊戲邏輯。

## 部署流程

1. 在 Supabase 專案 → **Authentication → Providers → Anonymous Sign-ins** 啟用匿名登入。主控與每位學生的裝置會有不同登入身分；不需要學生輸入帳號密碼。建議同時依 Supabase 官方文件設定防濫用／CAPTCHA。
2. 在 Supabase **SQL Editor** 貼入 `supabase/606-online-v2.5.0.sql`，一次執行。此 SQL 建立獨立資料表、受保護的機密資料、RPC、RLS、明確的 GRANT 與 Realtime publication。請先在獨立**測試專案**執行，避免與其他網站資料混用。
3. 開啟 `online-config.js`，填入 `url`（例如 `https://YOUR-PROJECT.supabase.co`）與 `publishableKey`（公開 publishable key 或 legacy anon key）。**絕對不可填入 `service_role`、`sb_secret_...` 或資料庫密碼。** 這是部署時的公開設定檔，會一起上傳到 GitHub Pages。
4. 部署整個網站資料夾（`index.html`、`online.html`、`online-config.js`、`assets/`），開啟「連線模式」。由主控端建立一些符合 3×3／4×4 的情報卡，勾選「啟用」。
5. 主控選宮格建立房間；學生在各自的手機開啟邀請連結（或輸入六碼房間代碼）並輸入代稱。主控看到 3～8 位玩家即可開始。
6. 學生私下展開身分卡、確認收妥；全部完成後主控擲雙色骰子。公開代碼不等於答案詞彙：只有情報員取得本輪隨機碼表，能將公開代碼對照到題卡的正確格子。臥底看不到碼表。
7. 主控抽取情報卡；全體裝置播放卷宗抽取動畫後顯示同一張卡。主控可選「投影情報卡」進入全螢幕題卡畫面。課堂討論與投票維持口頭／現場進行。
8. 依序「揭曉臥底」→「公布答案」→「建立下一輪」，沿用原房間成員重新隨機角色／對照表／骰子／情報卡。

## 雙骰公平規則

- **3×3：** 一顆正常六面骰（1～6）對應 A/B/C 各兩次；另一顆特殊六面骰的點數為 1/1/2/2/3/3，對應列 1～3。所有 9 格等機率。
- **4×4：** 八面骰（1～8）對應 A/B/C/D 各兩次；六面骰只接受 1～4，若擲出 5、6 則重擲。所有 16 格等機率。
- 真正亂數由資料庫產生，動畫不決定結果。公開代碼本身不足以識別詞彙，只有拿到本局隨機對照表的情報員可以解碼。

## 權限與注意

- Supabase 官方公告：**2026-10-30** 起，既有 Supabase 專案在 `public` schema 新增資料表不再自動取得 Data API 存取權；SQL 已使用明確 `GRANT` + RLS。
- 公開房間進度與共同情報卡透過 Realtime 更新（並每 5 秒補讀）；臥底編號、隨機碼表只保存在受保護的資料表，玩家只能透過授權 RPC 讀取自己的身分。主控直到揭曉才收到臥底編號；正確情報直到公布答案才提供全體。
- **匿名主控的情報卡與登入身分綁定當前瀏覽器**：若清除網站資料、更換裝置或登出，可能失去管理原有卡片與房間的能力。第一版適合測試；正式長期使用建議升級成教師電子郵件登入。
- 單機模式無需網路。連線模式需要 Supabase 和 CDN 正常運作；停用 JS 或缺少設定時會顯示錯誤。
- SQL 只保證獨立全新測試專案的首次部署；重複執行原 SQL 會因已存在的 RLS policy 發生錯誤，正式升級請使用個別 migration。
- 安全隔離仍需在實際 Supabase 專案以不同匿名身分進行整合／權限測試；未完成線上實測前請當作測試版使用。

# 606情報局｜誰是局外人？ v2.4.26

## 本次更新

- 以你最新提供的兩張乾淨版主視覺，重新製作臥底揭曉頁與機密代號揭曉頁。
- 臥底揭曉頁改為直接在素材原生銘牌上顯示動態「幾號玩家」與提示文字，不再用額外色塊覆蓋。
- 機密代號揭曉頁改為直接在素材原生卷宗中央顯示動態代號，不再用額外羊皮紙蓋住 A1。
- 情報員／臥底角色卡中的「本輪機密代號」「機密代號尚未取得」與代號本體整體下移一點，使視覺在框內更置中。
- 封存等待畫面與遊戲邏輯維持不變；仍保留 3～8 位玩家、固定一名臥底、共享同一機密代號與兩階段揭曉流程。

## 操作

1. 選擇場上玩家人數和情報表宮格，啟動機密任務。
2. **停用教室投影或鏡像**，依序讓每位玩家私下查看身分卡。
3. 全員完成後，可重新開啟投影，中央顯示機密封存畫面；玩家進行口頭發言，台下小組討論並在紙條投票。
4. 討論完畢後，教師點選「開啟封存卷宗／揭曉臥底」，確認後公開臥底編號。
5. 等臥底口頭推測，再點選「臥底猜測完畢・公布機密代號」揭曉正確代號。
6. 點選「建立下一輪機密任務」。

## 部署

把 `index.html` 與整個 `assets/` 一起部署到 GitHub Pages，保留相對路徑即可。無須後端、資料庫或 API。

## 注意

- 本站不記錄線索與投票；封存等待畫面不顯示任何人的身分。
- 素材中的「機密代碼封存中」是美術標題，遊戲功能統一使用「機密代號」。
- 臥底揭曉與代號揭曉已改用去除示例答案的新素材；動態文字直接置入空白區，不再需要額外遮蓋 A1 或 03 號玩家。
- 實際使用前應在教室投影設備再次確認文字大小。
