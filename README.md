# 606 情報局｜v2.5.6 連線模式功能更新

## 版本內容

以 **v2.5.4** 為基底，保留原有單機模式、Supabase 公開設定、情報卡資料庫與雙色骰機制。這次新增：

1. **主控端房間管理**：在主控區下方展開「⚙ 房間管理」，任何非關閉階段都能按「結束這個房間」，會有確認視窗；玩家端經即時通知或下次輪詢看到房間已關閉，不能再加入。僅等待玩家的 `lobby` 階段，教師可在名單旁移除誤加入的玩家。
2. **情報員共用代碼對照表**：每輪開始由 `intel606_host_action('start')` 在 Supabase 私密 schema **只產生一次**。3×3：18 格（9 代號 × 各 2 次）；4×4：48 格（16 代號 × 各 3 次）。所有情報員透過有授權的 `intel606_room_state` 取得同一張表；臥底和教師無法在未公開前透過 RPC 取得機密表或答案。情報員在個人畫面點「🔓 查看角色卡與共用代碼表」展開；確認收妥後保持展開，頁面切到背景會自動遮蔽。
3. **雙色骰子動畫**：主控端按「全員確認完成 · 公開抽骰」，**最終數值在資料庫抽取一次**，所有裝置根據 `dice_rolled_at` + `server_now` 同步播放約 3 秒滾動動畫（藍色六／八面、紅色六面），動畫結束後 RPC 才回傳最後的公開數值。3×3 紅骰為六面、1／2／3 各有兩面；4×4 紅骰為 1～6，不重擲。動畫期間不在 RPC 回傳當輪骰子最後數值和真正代號；重開頁面只會播放剩餘時間，不會重新擲骰。

## 部署至 GitHub Pages

更新整個 ZIP 的網站內容至 GitHub Pages。請確認 **`online.html`、`assets/online-v2.5.6.js`、`assets/online-v2.5.6.css`** 都已部署；實際 `online.html` 會引用這兩個新版本的外部檔案，而非舊的 v2.5.4 檔案。原有 `index.html` 單機模式未修改。

Supabase Project URL 與 **Publishable key / anon key** 可繼續從右上角「⚙ 連線設定」填寫；已在同一瀏覽器儲存的設定通常會保留。**切勿使用 service_role、secret key。**

## Supabase SQL（注意：必須先執行才能使用新功能）

- **已經部署 v2.5.1～v2.5.4 的資料庫：** 僅執行 `supabase/606-online-v2.5.4-to-v2.5.6.sql`。
- **全新的 Supabase 專案：** 僅執行 `supabase/606-online-v2.5.6.sql`，不要再另外執行升級檔。
- **仍是 v2.5.0 的資料庫：** 先在停止遊戲時，依舊有的 `606-online-v2.5.0-to-v2.5.1.sql` 升級，再執行 v2.5.4 → v2.5.6 升級 SQL。

### 為什麼這次需要 SQL？

新增 `public.intel606_rooms.dice_rolled_at` 用來記錄伺服器統一擲骰時間；更新 RPC `intel606_room_state`、`intel606_host_action` 讓骰點在動畫後公開；新增權限限制的 `intel606_remove_member`。SQL **不刪除現有情報卡或房間**，也維持公開資料表的明確 GRANT 和 RLS。舊有 SQL 備份一併附上供查閱，不要在已部署的專案重新執行「全新建立」SQL。

## 設計與安全注意事項

- 房間結束採 `phase='closed'` 的軟關閉方式，不直接刪除資料；要再玩請建立新房間。
- 移除玩家僅能由主控端在 `lobby` 執行；已開始遊戲的玩家不得任意移除，以免當輪臥底與人數不一致。
- Supabase `intel606_secrets` 仍在 `intelligence_private` schema 中，未加入 Realtime publication；只有具身分驗證的 RPC 可以檢查權限後回傳必要資料。
- 網頁上的雙色骰子動畫只是呈現效果；**真正的亂數在資料庫端抽取**，動畫不影響答案，也不能用自己的瀏覽器強制改變結果。
- 即時訂閱如短暫延遲，網頁每 5 秒會補抓進度；不同裝置不保證毫秒級同畫面，但最終結果和伺服器擲骰時刻一致。

## 後續正式驗收

本版已用 Chromium 搭配**模擬 Supabase RPC** 測試畫面互動與流程，並以靜態檢查確認 SQL 所需欄位與權限。**未連上你的真實 Supabase 專案、未驗證實際 SQL 執行與跨裝置網路同步**，部署後請先在測試專案驗收；測試表見 `TESTING.md`。
